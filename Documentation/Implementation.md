## Current playable mechanics

The rule model represents each fragment independently. Density now follows the candidate family found in native `SetCarrierBlockArgs`: 3×3 through 7×7 planes with depth 2 per color group, selected using route length and slot count. This implementation estimates route length from source control points; it does not reproduce remote-cohort/LoseConfig adjustments or the original Dreamteck spline measurement exactly. Level 1 selects 5×4×2 = 40 fragments rather than the earlier fixed 18. Fragment dimensions and all capacities scale together. Four groups still form an ordinary full truck. A click reserves outer contiguous matching-color blocks up to the available belt capacity. Complete blocks stay whole: if three match but only two fit, two are emitted. An outer block still being assembled can also be reversed, including landed fragments and incoming reservations, provided its current contents fit. Intake reservations prevent overbooking.

Conveyor movement now ports the inspected APK 4.6.0 BlockPhysicsSystem and shared Block jump body. The earlier moving-slot experiment and the later invented neighbor-separation/staggered-guidance implementations are superseded. Recovered native addresses, equations, parameters and remaining equivalence boundaries are recorded in NativeMovement.md.

Active fragments receive the native target-point force, with a 20-unit entry impulse, discrete collision detection, one solver iteration, gravity and interpolation. A static 256-sample 3D spatial hash replaces the per-step moving-block neighbor grid. Lane and height coordinates use the recovered native bounds and recovery rules. Fragment SphereColliders use radius 0.21 and the recovered zero-friction, 0.6-bounce material with Maximum combine modes; the track uses the default physics material.

Pause restores Rigidbody velocities on resume. Undo includes position, rotation, source and travelled distance; restart cancels prior flights. The inspected native movement and animation bodies have now been partially reconstructed and ported, rather than inferring behavior from component names. Dreamteck geometry, complete logical-slot scheduling, remote cohorts and remaining special mechanics still differ; this is not a claim of complete APK equivalence.

Placement starts from the source mouth/pivot, then tests each footprint against the sampled road and previously placed slots with extra clearance for the oblique camera. Undo restores the resolved positions. Track corners use circular fillets and dense arc samples for movement queries, with coarse generated surfaces and six-sided visual rails. Framing keeps every slot visible at a 70-degree pitch, using more vertical play space on larger levels, as requested by the user. It does not enforce a fixed zoom that crops larger layouts. The local default conveyor-speed factor is 5.5, from ConveyorConfig.Speed 5 and PaceConfig multiplier 1.1.

- Track geometry now follows the source BSpline, height suffixes, Subdivide count and open/closed state; open routes use end portals. The earlier invented overpass geometry is removed. See Documentation/NativeMovement.md.

The dense segment cache and binary route queries remain available for board placement, truck gates, landing projection and constructing the baked movement route. Normal belt motion now queries the static 256-sample spatial hash, rather than running a dense-segment route-window search for each moving fragment. The native sampler operates on the currently reconstructed curve; source Dreamteck percentage sampling and normals are not claimed to be identical.

Both outgoing and returning fragments now use the recovered shared jump: duration 0.7 times the local PaceConfig animation multiplier 0.5, InOutSine progress, Quaternion.Lerp, and the original sine/OutQuint vertical arc. The added fixed-outlet feed stage is removed. Landing alternates side offsets of -0.25/+0.25 and height +0.25 around the projected transfer point. Ordinary emission spacing uses slot collision distance divided by local unscaled speed and multiplied by the animation multiplier. Existing per-truck locks, interrupted-intake version guards and whole-block staging remain customized. Flight writes only Transform each frame; Rigidbody configuration and pose initialization occur at transitions. Belt entry applies the native impulse before ordinary physics resumes.

Visual verification caught a stale Rigidbody pose: newly activated cargo rendered at its cargo location while its physics position still read `(0,0,0)`, allowing interpolation to pull later launches toward the old origin. Animated transitions now disable interpolation and synchronize Rigidbody position/rotation together with the Transform. Physical belt motion re-enables interpolation only after initializing the landing pose. Pause/undo also use these transitions, with undo preserving linear and angular velocities. A dedicated regression checks physics/render pose agreement before and during the burst.

Exposed landed cargo eligible for the next release receives one black outline hull, using the same color and capacity selection as unloading; hidden or packed cargo is excluded, and the outline is restored after the preceding batch finishes unloading. Completed trucks stay in place with the APK carrier's standalone purple check sprite. The previous `day-base-played` daily-reward button was the wrong artwork; the carrier Image references sprite 687 (`checkerPurple`) and has no green background. HUD canvas sorting order 100 places dialogs and their dimming overlay above completion sprites at order 0. Hidden groups use the flowing question-mark cover. Source `H_color` carrier features now create closed colored curtains using source mesh 395 and its serialized transform. Closed slots hide cargo and reject transfer/shuffle. A fully completed matching-color truck opens all corresponding curtains; other colors and partial arrivals do not open them. Reveal/lock state is included in undo snapshots. This matches the native completion-event relationship observed in `HiddenCarrierSystem.HandleComplete`; its original Animator blend-shape animation is approximated by rolling back the exported mesh.

Loose fragments use the source normal-block scale on the belt (0.51 world units for the imported beveled mesh), with the recovered 0.21-radius SphereCollider. Packed fragments still use this project's adaptive FragmentLayout cell size. Scale switches at transfer boundaries rather than using the superseded smooth growth animation. Whole-group density and capacity rules remain the project's customized reconstruction.

Release clicks do not wait for global transfers. Different trucks unload concurrently, but the same truck ignores further clicks until the last fragment of its current batch has landed on the belt. Clicking during intake can reverse the outer block and its matching neighbors. Selected incoming reservations and landed fragments reserve belt capacity together before any animation changes; insufficient capacity leaves an unselected block and its intake unchanged. Reversed fragments keep their current airborne pose and size. Each new transfer increments a per-fragment version so obsolete receive animations cannot move or complete a reversed fragment, even after a later collection. The per-truck releasing count participates in undo and restart. Shuffling checks only the chosen truck, and adding a spare truck does not wait on unrelated animations.

Each successful release records its color on that truck. When the truck is empty, intake gives priority to other colors already on the belt or reserved for outgoing flights, even if the emitted color reaches its gate first. If no alternative color is available, the emitted color can enter again. Occupied trucks still accept only their exposed front color. The preference is independent for each truck, survives undo through carrier snapshots, and resets with a new level. Color availability is maintained incrementally on release and intake reservations and rebuilt on snapshot restore, avoiding a scan through all pieces on every intake check.

Overlapping operations share the most recent stable undo checkpoint. Undo can immediately cancel the whole overlapping wave, restore cargo/physics state and invalidate every previous callback; it never restores an orphaned Releasing/Receiving state. A later click after transfers have settled starts a new checkpoint. Restart cancels all concurrent flights. Undo does not refund consumed boosters.

Hidden cargo is covered until exposed at the front of an accessible truck. All 1,299 main levels remain selectable. Barrier, ice, key/lock, color-tag, rope, screw, carpet and finite generator queues now execute from imported source annotations, in addition to hidden cargo and curtains. These states participate in undo. Only records 450 and 972 retain an unhandled block annotation and gold level numbers; fallback does not disable their already implemented mechanics. Strict GameState callers still reject unhandled records unless fallback is explicitly enabled. Import coverage is 1,297 records without unhandled markers, not 1,297 validated or solved levels. See NativeMechanics.md for evidence and remaining animation/layout differences.

## Cargo display and fixed-update performance

Release capacity and ownership are reserved for the entire accepted batch at click time, but its full blocks are queued visually rather than exposed as loose fragments immediately. Emission visits the outermost group first, then its outlet-facing depth layers, top rows and successive columns. A fragment becomes visible only when its feed animation starts. Blocks whose turn has not arrived retain their original full mesh and material. For the active block, the unlaunched volume is represented by up to three solid rectangular remainders derived from the original mesh bounds; deeper layers, lower rows and the rest of the current row shrink only as their fragments are emitted. Two additional pooled models per truck are reused across all its groups, with dirty updates still coalesced per frame. Existing partial intake fragments keep their current pose when reversed. Pause stops the queue, and undo or restart clears its visual staging alongside the existing transfer cancellation.

Ordinary intake reservations and arrivals mark the affected truck dirty instead of rebuilding every truck for every received fragment. LateUpdate refreshes each dirty truck at most once per frame; changed completion and curtain states are also detected there. Occupancy or capacity changes invalidate outlines separately, so other trucks do not need their cargo displays rebuilt. Loading, undo and adding a truck retain synchronous full-display refreshes for those explicit transitions.

Each truck creates four reusable full-block models, two shared solid peel-remainder models and one outline when it is constructed. Subsequent refreshes change visibility, material and bounds without destroying or recreating these objects. Partial intake blocks reuse the persistent fragment views; full blocks queued for release retain their solid meshes until their scheduled emission. Renderers and displayed cargo slots are cached; unchanged settled fragments do not repeatedly reset their transforms and Rigidbody poses. A received fragment still finishes its rule transition and reaches its reserved position immediately, before the display work is coalesced.

FixedUpdate maintains a reusable active belt-view list. Landing adds a view and intake removes it by swapping the final entry; the replacement is processed before advancing. Each body position is read once, queried against the immutable baked route index and passed through the native constraint/force step. There is no moving-neighbor buffer, grid rebuild, separation scan or group-phase cache. Logical travelled distance and gate checks remain for the project's customized intake rules.

Physics timing now follows the verified native BuildMessages setter calls: fixedDeltaTime 0.0333 and maximumDeltaTime 0.05. Source project defaults and fragment overrides use one solver iteration and one velocity iteration. Collision detection is Discrete, maximum linear speed 20, maximum angular speed 50 and rotation constraints None. The native force/constraint step runs for all belt fragments at the restored rate. No post-edit compilation, tests, visual comparison or profiling were run, as requested; no measured frame-rate improvement is claimed.

Belt occupancy and pending-transfer counts are maintained incrementally. Reversing an incoming fragment does not count it as a second pending transfer. Snapshot restoration rebuilds both counts and the per-color occupancy cache. This removes repeated full-piece scans from intake, display capacity checks and ordinary transfer bookkeeping. The later native-movement recovery replaces the previous physical settings and timestep, as described above. No post-edit compilation, tests or performance sampling were run, as requested; the resulting timing improvements remain unmeasured.
